TL;DR — what we're doing and why

Chat-CLI today emits telemetry through two hand-rolled channels (PostMetrics via SigV4/Cognito + SendTelemetryEvent via Bearer) routed asymmetrically across 20 (V1) and 23 (V2) EventType variants. The schema lives in three drifting JSON copies. We have zero observability of the telemetry pipeline itself, no PII redaction, no opt-out end-to-end test, and no per-version active-user gauge.

This design replaces both channels with an OpenTelemetry Rust SDK (pinned ~0.32.0) emitting OTLP/HTTP to a team-owned ADOT collector that exports EMF to CloudWatch — with one canonical schema crate, a hard cardinality budget enforced at the SDK boundary, paired success/violation counters that prove privacy, and a 4-phase rollout that holds dual-write parity gates before retiring legacy.

Background — what telemetry exists today

Two channels, three schemas, no self-observability

Two emission channels, asymmetric routing

  • Channel A — PostMetrics (Toolkit Telemetry, SigV4 via Cognito identity pool us-east-1:820fd6d1-95c0-4ca4-bffb-3f01d32da842, hardcoded EXTERNAL_PROD) at crates/chat-cli/src/telemetry/mod.rs:137-141. Routes all EventTypes via into_metric_datum() (mod.rs:778-808).
  • Channel B — SendTelemetryEvent (CodeWhisperer ApiClient, Bearer from auth.builder_id). Per mod.rs:680-775, only ChatAddedMessage and AgentContribution match; the other 18+ variants no-op.
  • GovCloud (US_GOV_EAST / US_GOV_WEST) hard-skips Channel A at mod.rs:213-234 — partition-aware, but unproven by metric.

Goals & non-goals

P0/P1/P2 with explicit non-goals

P0 — must ship in Phase 1

  • G1. Single schema source of truth (kiro-telemetry-schema) replacing 3 JSON copies.
  • G2. OTel SDK at the boundary; no direct calls to Toolkit Telemetry from product code.
  • G3. CloudWatch alarm parity ≥30 days within 0.5%.
  • G4. Privacy proof points: opt_out_violation_total = 0, govcloud_channel_leak_total = 0, pii_redaction_coverage_ratio ≥ 0.999, end-to-end opt-out test in CI.
  • G5. Cardinality budget enforced at SDK boundary (closed enums, _other_ bucketing, runtime limiter, CI lint).
  • G6. Telemetry-on-telemetry: P0 self-observability set ships day one.

P1 — first PM dashboards (Phase 2)

  • G7. Adoption KPIs: DAU/WAU/MAU, version_adoption_pct, dau_mau_ratio, new_users_daily.
  • G8. Funnel/cohort fact tables: kiro_cli_client_identity, kiro_cli_first_message_sent, kiro_cli_user_turn_completed, kiro_cli_conversation_completed.
  • G9. Conversation outcomes + token economics: per-turn token counts on the fact row, kiro_cli_estimated_cost_usd counter, server-side MeteringEvent reconciliation.

Non-goals

  • New metrics backend (we use ADOT → CW EMF; inherit KUTS later).
  • Tracing on day one (Phase 5+).
  • Per-user_id metrics (user-level lives in fact tables, never metric dims).
  • Removing Toolkit Telemetry until parity is proven (dual-write through Phase 3).
  • Preserving the Toolkit/CodewhispererTerminal namespace path — consumers MUST migrate.

   Telemetry-on-telemetry pipe is a SEPARATE direct PutMetricData
   (~20 series, 5-min interval) so it does not share fate with OTLP.
  • Inheritance. OTel semantic conventions (GenAI, HTTP), Prometheus naming, ADOT awsemf exporter — we stop maintaining a bespoke pipeline.
  • Pipeline self-observability. OTel SDK self-instrumentation + meta-meter give us drop/queue/cardinality counters Channel A/B never had.
  • Standard transport. OTLP/HTTP-protobuf; no tonic/gRPC dep on customer laptops.
  • KUTS-ready. When KUTS GAs, swap one exporter; product code unchanged.
  • Auth posture preserved. SigV4 via the existing Cognito chain — same trust boundary as Channel A. No baked Bearer token ships in the binary.
Cardinality rules — enforced in code, not review.
  1. Every metric attribute is a closed Rust enum in schema/types.yaml. _other_ bucket always present.
  2. Never as metric dims: user_id, anonymous_client_id, session_id, conversation_id, request_id, tool_use_id, panic_location, host_id_hash, reason_desc, raw MCP/custom tool_name. → log/exemplar only.
  3. version_full only on client_version_seen gauge with LRU 200; elsewhere use version_minor bucketed.
  4. tool_name splits into builtin_tool_name (registry enum) + tool_origin ∈ {builtin, mcp, custom, subagent_delegate, aws_api}.
  5. mcp_server_name on metrics collapses to mcp_server_class.
  6. ADOT attributes processor allowlist drops everything else.
  7. Per-metric series cap default 5,000; runtime limiter trips telemetry.cardinality.overflow_total.
  8. CI lint walks workspace; fails on any MetricDatum::builder() outside facade or schema crate.
  9. Per-instrument temporality: Counter/Histogram = Delta; UpDownCounter/ObservableGauge = Cumulative.

Backwards compatibility

Kibana / Channel-A consumer migration

Inventory required before Phase 2 exit. docs/oncall/telemetry_migration_kibana_consumers.md enumerates:

  1. The five SEV alarms in account 421629052180 and their owners.
  2. ToolkitTelemetryInfrastructure/qcli-metrics.ts Kibana saved searches.
  3. Kinesis-fed dashboards keyed on Toolkit/CodewhispererTerminal namespace.
  4. MeteringEvent consumers (finance — additive new wiring).
  5. External consumers of aws-toolkit-telemetry-definitions/def.json codegen.

Migration paths

  • Legacy metric continuity (Phase 1-3): dual-write. CloudWatch dashboards keep rendering.
  • Alarm parity (Phase 2): shadow alarms with -shadow suffix for ≥30 days; Δ < 0.5% for 14 consecutive days; legacy armed through Phase 4.
  • Kibana migration (Phase 2 exit-blocker): every saved search rewritten as Athena query; owners sign off in writing.
  • Schema migration (Phase 4): def.json retired iff external-consumer count = 0; otherwise frozen as one-way generator.
Explicit non-goal: the Toolkit/CodewhispererTerminal namespace is not preserved. Consumers migrate to ChatCLI namespace within Phase 2 or accept deprecation.

Test strategy & open questions

8 test gates including missing opt-out E2E

Open questions (need decisions before Phase 0 PR)

  1. Sidecar ADOT vs regional ADOT? Recommendation: regional team-owned ADOT, SigV4 via Cognito.
  2. Cognito SigV4 reuse vs new IAM? Recommendation: reuse existing chain — same trust boundary, retires cleanly in Phase 4.
  3. Workspace dep graph. Only telemetry crates depend on kiro-telemetry-schema.
  4. Event IPC format. Keep through Phase 1-3; introduce kiro_telemetry::record!() macro for new metrics; deprecate in Phase 4.
  5. Account ownership. Recommendation: dedicated chat-cli account for OTel EMF.
  6. Sampling for high-volume CLIs. Bounded queue + P-tier dropping at backpressure.

Test gates (block Phase 0 exit)

(a) Unit tests — in-memory OTel reader

InMemoryMetricExporter; every EventType → metric mapping has a test asserting name, unit, attribute set, attribute values, temporality.

(b) Schema contract — EMF byte-equality

Instantiate each metric, run through both legacy and OTel sinks, assert EMF JSON byte-identical for the dimensions read by the 5 SEV alarms. This is what protects production. Failing this test blocks merge.

(c) Mock OTLP collector — integration tests

Spin up otelcol in test (Docker), point binary at it, run q chat against a recorded Bedrock cassette; decode protobuf via opentelemetry-proto.

(d) Opt-out E2E (the missing test)

The test that does not exist today. Three parts:

  • In-process fuzzed (proptest): every EventType with random fields under KIRO_TELEMETRY_ENABLED=0 → assert zero sink calls, zero state-dir bytes, zero outbound HTTP.
  • Cross-process binary test: spawn actual binary; point OTEL_EXPORTER_OTLP_ENDPOINT at a sink that fails on any received request.
  • Spool semantics: spool with telemetry on, restart with opt-out; assert spool is empty before any export attempt and spool.purged_on_optout_total increments.
(e) GovCloud build verification

Compile-time assertion that legacy commercial sinks are unreachable; runtime test asserts only outbound is GovCloud ADOT.

(f) Cardinality CI check

Static lint walks attributes!() and KeyValue::new; rejects any attribute key not in schema/types.yaml. Fuzz emits 10k distinct values per dim; runtime limiter caps at budget.

(g) Drop accounting invariant

Synthesize session that emits, retries, drops; assert success + permanent_failure + dropped == emit_count per signal.

(h) Load test (out-of-band)

k6 drives 10k synthetic CLI invocations/sec for 1h. dropped{queue_full}=0, queue p99 < 50% capacity, p99 export latency < 1s, ADOT memory bounded.

C — Example OTel Rust setup 
// crates/kiro-telemetry/src/lib.rs (sketch)
use opentelemetry::{global, KeyValue};
use opentelemetry_sdk::{
    metrics::{PeriodicReader, SdkMeterProvider, Temporality},
    Resource,
};
use opentelemetry_otlp::{MetricExporter, WithExportConfig, Protocol};
use std::time::Duration;

pub fn init(cfg: TelemetryConfig) -> anyhow::Result<SdkMeterProvider> {
    if !cfg.opt_out_gate.allow_init() {
        cfg.respected_counter.add(1, &[]);
        return Ok(no_op_provider());
    }

    let exporter = MetricExporter::builder()
        .with_http()
        .with_protocol(Protocol::HttpBinary)
        .with_endpoint(cfg.endpoint)            // SigV4 via Cognito
        .with_timeout(Duration::from_secs(30))
        .with_temporality(Temporality::Delta)
        .build()?;

    let reader = PeriodicReader::builder(exporter)
        .with_interval(Duration::from_secs(60))
        .build();

    let resource = Resource::builder()
        .with_attribute(KeyValue::new("service.name", "kiro-cli"))
        .with_attribute(KeyValue::new("service.version", env!("CARGO_PKG_VERSION")))
        .with_attribute(KeyValue::new("partition", cfg.partition.as_str()))
        .build();

    let provider = SdkMeterProvider::builder()
        .with_reader(reader)
        .with_resource(resource)
        .build();

    global::set_meter_provider(provider.clone());
    Ok(provider)
}
